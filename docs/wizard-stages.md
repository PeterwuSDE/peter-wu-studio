# 网站生成向导 · Stage 设计

## Context

Northline Studio 需要一个**前端获客工具**：潜在客户在工作室网站上走完一个引导式向导，
一步步构建出自己网站的雏形；工作室在末端拿到一份结构化需求（spec + brief + 联系方式），
并负责后续的 deploy 与 host。

本文件只定义**流程阶段设计**——每一步问什么、为什么这么排、LLM 在哪里介入。

配套文档：[`wizard-spec-schema.md`](./wizard-spec-schema.md) —— spec 的形状与解析规则。
其余实现方案（Cloudflare Worker 路由、区块组件抽取）另行设计。

### 已确认的前提

- **部署**：主站迁到 Cloudflare Worker（`worker/index.ts` 已存在但未使用），
  LLM 密钥用 wrangler secret；GH Pages 保留为无 LLM 的降级版
- **交付**：由工作室负责 deploy 与 host —— 因此终点 CTA 不是"下载代码"
- **LLM 职责**：文案生成、配色/字体推荐、结构推荐、自由对话微调，四项全要
- **v1 深度**：一套区块库 + 参数化主题（复用现有站点的区块语汇）

### 对原始设想的一处调整

原设想顺序为「框架 → 颜色 → 排版」。**"框架"不暴露给客户**：
对纯内容站，技术框架是工作室的决策，客户答不上来，问了只制造焦虑。
客户要选的"框架"是**站点结构**（要讲哪几件事、什么顺序）；
技术框架由结构 + 托管方式静默推导。

---

## 五条贯穿原则

1. **每一步收窄下一步** —— 前面的答案过滤后面的选项，客户看不到会出错的组合
2. **给指认，不给填空** —— 除事实性问题外，全部视觉化二选一/三选一
3. **预览从第一步就开始长** —— 不是走完才看到成果
4. **护栏在系统里** —— 对比度、字阶、间距节奏由算法保证，客户"改不坏"
5. **进度用设计师语言** —— 显示 `定位 · 气质 · 结构 · 配色 · 排版 · 内容 · 上线`，
   而非 "第 3/7 步"；流程条本身传达专业度

## Stage 0 · 意图

- **形式**：三选一，无输入。作品集/品牌展示 · 服务型商家 · 活动或产品单页
- **作用**：决定后续所有默认值的骨架
- **目的**：零门槛迈进门
- **LLM**：不介入

## Stage 1 · 定位（= discovery call）

全流程唯一大量文字输入的一步。三问：

1. 你是谁（名字 + 一句话业务）
2. 给谁看（目标客群）
3. 看完希望他做什么 —— 看作品 / 打电话 / 预约 / 留资

- **LLM**：做**归纳**而非生成 —— 把口语整理成一句 positioning statement 交客户确认。
  该句是后续所有文案生成的 system context，也是最终 brief 的第一行。
- **下游影响**：第 3 问（CTA 目标）直接改变 Stage 3 的区块排序

## Stage 2 · 气质（全流程最关键）

- **形式**：6 张**同一份内容、不同气质**的缩略图；选 2 张喜欢 + 1 张明确不喜欢
- **一次点击同时锁定**：配色倾向、字体倾向、留白密度、图形语言、动效强度
- **产出**：tone vector —— `克制↔大胆`、`经典↔当代`、`温暖↔冷峻`、`密集↔疏朗`
- **LLM**：根据 Stage 1 预先高亮推荐 2 张 + 一句理由
- **理由**：这是把"审美"从抽象讨论变成可执行参数的唯一可靠办法

### 已决：用**真实区块实时渲染**，不用预渲染静态图

所见即所得，选完不落差；区块库反正要建，不算额外成本。

**实现要点**：不要用 6 个 iframe（6 个 React root 太重）。
现有 `app/globals.css:3-12` 的设计系统已经是纯 CSS 变量驱动，
只需把 `:root { --ink/--paper/--blue/... }` 改为 `.theme-scope { ... }`，
则同一棵 React 树可在 6 个不同 token 值的 `.theme-scope` 容器里渲染出 6 种气质，
外层用 `transform: scale()` 缩成缩略图。这是现有 CSS 架构的直接红利。

**连带影响（关键排期约束）**：
Stage 2 依赖渲染器存在 → **区块库 + token 系统必须先于向导 UI 建成**。
实现顺序因此被锁定为：
`spec schema → 区块库 + token 系统 → 渲染器 → 向导外壳 → LLM 路由`

## Stage 3 · 结构（= 原本说的"框架"）

- **形式**：推荐一套区块顺序，可开关 + 可拖拽
  `首屏 · 你是谁 · 作品/服务 · 工作流程 · 信任 · 常见问题 · 联系`
- **客户只做**：删不需要的、调顺序、单页 or 多页
- **LLM**：解释为什么是这个顺序（"你选了『预约』，所以联系区块提到了作品前面"）
  —— 让客户感到被设计过，而非随机模板
- **静默推导**：技术框架在此确定（单页 → 静态导出；多页/博客 → 加内容层），客户无感

## Stage 4 · 配色

- **形式**：3–4 套完整方案（纸张色 / 墨色 / 主色 / 强调色），
  已由 Stage 2 的 tone vector 过滤；**直接渲染在客户自己的雏形上**（看的不是色卡，是自己的网站）
- **微调**：只开放"主色"一个维度，其余算法跟随
- **护栏**：WCAG AA 对比度自动校验，不通过的组合不出现在选项里

## Stage 5 · 排版

- **形式**：3 套**字体配对**（标题 + 正文），不是字体下拉列表
- **单独的密度开关**：`疏朗 / 标准 / 紧凑` —— 一个开关同时改行高、区块内边距、字号阶梯
  （一个滑块比五个滑块可控得多）
- **中文站点**：额外处理中西文混排字体栈 —— 明显的专业度差异点

## Stage 6 · 内容

- **顺序理由**：骨架/颜色/排版都定了，**现在**才填内容
- **形式**：LLM 基于 Stage 1 positioning + Stage 2 tone 生成整站首稿；
  客户看到的是**已填满的网站**，只需就地编辑（inline edit），而非面对空表单
  —— 这个顺序差别，是"能走完"和"走不完"的差别
- **每个字段**：一个「再写一版」按钮
- **资产**：Logo 没有就先生成字标；图片先用占位

## Stage 7 · 成型与交付

- **形式**：全屏预览，桌面/移动切换
- **唯一转化点**：客户此刻正看着自己的网站
- **CTA**：「由 Northline 上线并托管」—— 不是下载代码
- **工作室收到**：完整 spec + 联系方式 + 自动生成的项目 brief（建议工期 + 报价区间）

### 已决：报价用**规则表计算**，不用 LLM 估算

报价是商业承诺，模型报错要由工作室兜底 —— 不交给 LLM。

维度：基础价 + 区块数 + 单页/多页 + 是否要博客/内容层 + 是否要 logo 设计。
存为一份独立的、Peter 可随时手改的价格配置（如 `lib/pricing.ts`），
**不埋进组件里**。输出给客户的是区间而非定值。

## 三个横切设计

### 常驻对话框（不是 stage）

预览旁常驻输入框，任何时候说"再高级一点""配色冷一些"直接改 spec。
**约束**：LLM 只能输出合法的 spec diff，不能自由改代码。

### 流失点管理

**已决：保持完整 7 步，重专业感** —— 目标是筛出高意向客户并拿到完整 brief，
而不是最大化完成率。流程本身就是工作室方法论的展示。

代价是流失风险，靠三件事对冲（因为选了 7 步，这三件从"可选"升级为**必做**）：

- Stage 0–2 **不要任何邮箱或注册** —— 先让人尝到甜头
- Stage 6/7 之前才要联系方式 —— 此时沉没成本已高
- 每步自动存 spec + 生成可分享链接，允许中断续做
  （v1 用 localStorage；要跨设备续做再上 `.openai/hosting.json` 预留的 D1/R2）
- 进度条用 `定位 · 气质 · 结构 · 配色 · 排版 · 内容 · 上线` 全程可见，
  让客户随时知道"还剩几步"——7 步的心理负担主要来自不确定，不是数量

### 可回退不可破坏

客户回到 Stage 2 换气质时，Stage 4/5 中他**手动确认过**的选择应尽量保留。
要求 spec 中 tone / color / typography 三层**解耦**，而非级联覆盖。

## 实现顺序（由 Stage 2 的决定倒推）

不能先做向导 UI —— Stage 2 要实时渲染真实区块，渲染器必须先存在。

1. **spec schema** —— tone / color / typography / structure / content 五层，前三层解耦
2. **token 系统** —— `app/globals.css` 的 `:root` 变量提取为 `.theme-scope`，支持同页多主题
3. **区块库** —— 从 `app/page.tsx` 抽出 hero / intro / work / services / process / faq / contact
   七个区块为组件，内容从 props 进（现在是硬编码的 `projects`/`services`/`faqs` 数组）
4. **渲染器** —— 消费 spec 输出完整页面；Stage 2 的 6 张缩略图是它的第一个消费者
5. **向导外壳** —— 7 步状态机 + 进度条 + localStorage 续做 + 预览面板
6. **Worker LLM 路由** —— 启用 `worker/index.ts`，加 `/api/*`，密钥走 wrangler secret
7. **定价表 + brief 生成 + 提交回流**

其中 3 是最大的一块，也是唯一会改动现有站点的一块 —— 现有站点应当成为
"用这套区块库渲染出的第一个 spec"，这样区块库的质量有真实基准，不会退化成通用模板。
