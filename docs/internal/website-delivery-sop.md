# 网站项目内部交付 SOP

适用：Northline Studio 的新建展示网站与 Modernization。本文为内部方法库，承接[网站标准服务](../website-standard-service.md)，不单独扩大套餐范围。所有可选步骤先核对项目提案；工具列表表示可选方法，不代表当前已部署自动化能力。

原文档中的盘点、诊断、信息架构、设计、原型、迁移与交接方法在这里维护；对客服务边界由上面的服务定义维护。外部 Canvas 只用于讨论，正式修订进入 GitHub。

## 1. 阶段、收费与自动化边界

| 阶段 | 可做的工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 免费入口 | 按已定稿设计读取一个首页 HTML 与响应头，返回真实基础发现 | 客户自主联系，不要求先留资 |
| 初步沟通 | 整理客户主动提供的需求，判断服务类型、预算和资料缺口 | 提案、合同和约定启动款确认 |
| 付费发现或诊断（如单独购买） | 在明确页面与工具预算内盘点、检测，交付证据与优先级 | 后续设计或实施另行确认；不自动续购 |
| 已启动的网站项目 | 按约定范围发现、设计、原型、开发、验收、上线及交接 | 每阶段按约定反馈和付款节点推进 |
| 上线后 | 14 天交付缺陷保障；可选 Care；单独的 SEO 合作 | 新范围需确认，不自动订阅 |

**付款前不运行消耗 LLM token 的客户分析、访谈整理或内容生成。** 联系表单不触发付费 API、深度浏览器采集或完整版报告。付款后仍按已约定的工具、数据权限、用量与预算执行，不能因为客户付了建站费就无限运行竞品或 AI 可见度分析。

免费入口严格使用[首页体检定稿](../superpowers/specs/2026-10-29-northline-homepage-seo-check-design.md)：不渲染浏览器，不读取 robots/sitemap，不沿站内链接，不运行 Lighthouse，不拉取竞品或 Google 商家资料，不提供全站分数，不持久化完整 HTML。免费服务的安全、限流、缓存和保留期限以该设计为准。

以下 robots、sitemap、截图、媒体存档、Lighthouse 和人工走查只适用于已授权、已启动且范围包含这些工作的付费阶段。网站项目阶段不作为免费工具的默认后端。

## 2. 立项记录与范围基线

立项建立项目简表、资料责任表、访问权限表和范围表：

| 类别 | 必填或按适用情况确认 |
| --- | --- |
| 业务 | 目标客户、主要行动、语言与市场；仅本地业务需要城市、服务区与营业信息 |
| 成果 | 页面 URL 与模板数量、内容条数、语言版本、设计方向和反馈轮次 |
| 技术 | 现有平台、域名/DNS、托管、部署、CMS 需求和第三方依赖 |
| 迁移 | 公开内容、媒体、旧 URL、私有数据分别列清单与数量 |
| 采集预算 | 授权域名与路径、页面上限、深度、并发、速率、超时、媒体及截图上限 |
| 协作 | 客户决策人、资料责任人与期限、反馈窗口、授权及付款节点 |
| 验收 | 设备/浏览器、性能测试条件、关键路径、上线窗口及回滚方式 |
| 数据 | 哪些可存档、谁可访问、保留与删除时间、外部工具处理权限 |

站点规模无法判断时先做已付费的有限发现阶段，再确认实施预算。不能把“全部内容”或“12 页以上”当成无上限范围。发现内容、功能或数据超出清单时，先记录缺口并提出变更。

账号采用必要的协作授权，不把密码、访问 token 或私有业务数据放进仓库。平台无法授权或访问受限时记录阻塞，不绕过登录、验证码或挑战页。

## 3. Modernization 流程：从旧站到上线

输入网址 → 确认范围与启动 → 授权盘点 → 现状诊断 → 信息架构与 URL 处置 → 设计与预览 → 开发与迁移验证 → 验收上线 → 交接与保障。

### 3.1 授权盘点

**输入：**项目简表、授权域名/路径与采集预算、客户素材、必须保留的内容和功能。

**方法：**读取付费项目范围内的 robots 与 sitemap，核对导航与内链；优先使用正常 HTTP，确需渲染时可选 Playwright。仅在授权和数量上限内提取内容、结构化数据、媒体元信息和截图，不批量遍历业务数据库。

**产出：**

- URL 表：状态码、页面类型、标题、描述、H1、主要内容、内链及保留/合并/删除建议。
- 结构与内容：导航树、范围内文案存档、素材授权与缺口清单。
- 素材表：图片用途、alt、尺寸、体积、来源与使用权；下载仅限允许存档的资产。
- 功能表：表单、地图、预约链接或嵌入、分析脚本和其他依赖。
- 截图：约定首页与关键页面的桌面/移动端基线。

**人工检查：**对账已纳入范围的 URL；超限、未覆盖、受限或失败项目明确列出；客户确认联系方式、业务描述、服务、价格与营业时间。页面上的旧事实不直接当作新站事实。

### 3.2 现状诊断与基准

**输入：**盘点、截图、客户目标、约定测试结果；客户提供的 GSC/分析只读数据可选。

**产出：**一页摘要、带 URL/截图/指标的发现、影响与修复难度、优先级及建议行动。没有校准方法时不用加权总分；Lighthouse 单项分数保留工具名称与测试条件，不改称“SEO 实力分”。

**方法：**可选 Lighthouse、PageSpeed Insights、axe、元数据检查、人工移动端关键路径测试和公开配置检查。真实用户 Core Web Vitals 仅在有可用数据时报告；不能用 Lighthouse 替代真实用户体验结论。

**基准记录：**

| 对比类型 | 记录与解释 |
| --- | --- |
| 改版前后实验室测试 | 同一代表页面集合、设备/网络/工具配置与运行方法，记录时间和第三方脚本变化 |
| 真实用户表现 | 标明来源、时间窗口、页面或站点粒度；无数据标记不可判断 |
| 客户搜索表现 | 仅在取得授权且范围包含时比较；说明时间窗口、季节性及归因限制 |
| 竞品参考 | 最多按提案约定数量进行公开页面人工参考；只比较实际观察，不能推断其后台、收入或转化率 |

**人工检查：**每条发现区分已验证问题、需确认信号与无法判断项；对技术债、备份、CMS 版本和安全问题，不能只凭网页指纹作确定结论。

### 3.3 信息架构与 URL 处置

**产出：**新页面与模板清单、导航、每页主要行动、内容责任、线框级区块、新旧 URL 处置表。

| 旧页面情况 | 处置 |
| --- | --- |
| 地址与内容保留 | 保持原 URL 正常返回 200 |
| 迁移或合并且有相关替代内容 | 设置到对应目标的永久重定向，避免链与环 |
| 删除且没有相关替代内容 | 明确 404/410，并修正站内链接；不统一跳首页 |
| 应保持私密或不收录 | 保留相应访问/索引限制；不为追求清单通过而移除 |

**人工检查：**重要内容与业务路径可达；新增页面有真实用户价值；本地服务区页面只在业务真实且有独立内容时制作，不批量生成空洞地域页。上线前由客户确认内容保留与删除决定。

### 3.4 设计与原型

**输入：**确认的结构、真实内容或已确认缺口、已有品牌与素材、参考偏好。

**产出：**范围内视觉方向、排版与配色、间距与布局、核心组件、高保真稿或代码预览。设计方向数量、关键页面数和评审轮次按提案；不默认承诺两个方向或首页外额外页面。

**方法：**可选 Figma、设计令牌、对比度检查；付费阶段可在授权范围内用模型辅助草稿或探索，全部经过人工审阅。使用现有或适合项目的技术栈，不把 Astro、Next.js、Tailwind 或特定托管平台作为统一购买前提。

**人工检查：**桌面/移动端视觉、品牌一致性、可读性、焦点与关键交互；文案符合客户确认事实。原型演示与生产功能分清，演示表单不可假装已经送达，演示预约不可冒充真实系统。预览站使用合适的访问/索引限制。

### 3.5 开发、验收、上线与交接

结构和设计确认后，进入第 5 节共同交付阶段。Before / after 是项目演示材料，不是“先免费制作原型、再决定是否付费”的默认流程。公开发布对比图前单独取得书面营销许可。

仅出售诊断或设计的项目，在对应交付物验收后结束；后续开发、上线和 Care 需要新确认，不自动执行。

## 4. 从零建站：前期资料路径

确认范围与启动 → 需求与资料 → 定位与内容 → 信息架构 → 设计与原型 → 第 5 节共同开发、上线与交接。

### 4.1 需求与资料

**输入：**业务负责人访谈/问卷、已有品牌与素材、目标客户、期望行动、语言与市场。没有实体门店的客户不强制填写地址或营业时间。

**产出：**项目简报、已有/缺失资料清单、责任人与期限、授权清单。访谈录音或转写须事先取得同意；付费后才可按权限和预算用模型整理。未经批准的个人信息不发送给外部模型。

**人工检查：**所有关键业务事实由客户确认；案例、评价、资质和成果不得编造；没有足够素材时先说明缺口，不用虚假内容填满页面。

### 4.2 公开信息与竞品参考

- 仅在付费范围包含时，整理客户自有公开渠道或客户提供的导出资料；Google 商家资料仅用于适合且符合平台条件的业务。
- 客户社交内容不绕过登录获取；第三方点评、照片、字体和图库素材核对使用权，不直接复制。
- 竞品只做约定数量的公开页面人工参考，记录结构、信息表达、主要行动与视觉特点。不对竞品运行自动爬虫、批量素材下载或 Lighthouse。
- 可自动整理已授权、已取得的资料；人工核实来源与日期、事实和版权。需要关键词或第三方数据工具时先核对付费范围与预算。
- 不收集公开评论中的顾客个人资料。没有客户确认的信息标为待确认，不从模型猜测。

### 4.3 品牌与内容

**标准范围：**整理客户已有 Logo、字体、颜色与图片，在网站中形成一致表达；整理客户提供的内容并进行约定的轻量润色。

**另行约定：**新 Logo、字标、完整品牌指南、商标检索、线下物料、从零文案、额外语言、拍摄或外部摄影协调。不得因为客户没有品牌就默认赠送完整设计服务。

**产出：**适用的网页风格规范、页面文案与元数据、素材清单和客户审批记录；摄影或图库仅在约定范围内提供方案与授权记录。

**人工检查：**全部事实、语气、审美、素材来源和对外承诺；不把初步名称检索描述为法律确认。文案与图片尽量在页面制作前确认，未齐备部分有责任人和期限。

### 4.4 结构与设计

复用第 3.3、3.4 节的页面结构、主要行动、视觉与评审方法。新站不需要旧 URL 映射；如已有旧域名或临时网站需要替换，仍核对迁移范围。不默认加入本地页面、预约系统或 Shopify。

## 5. 共同交付阶段

### 5.1 开发与内容装配

- 按确认范围实现响应式页面、基础 SEO 与可访问性；代码审查和构建检查与技术栈匹配。
- 可采用静态站，不默认附带 CMS。需 CMS 时先确认编辑内容、角色、操作说明与平台费用，并让客户演练约定更新。
- 表单明确字段、接收端与失败状态，实际测试送达；对预约、地图、分析与其他集成逐项核对是否包含。
- 外部预约链接/嵌入与自定义业务系统分开；Shopify、电商、会员、权限与排班走独立范围。
- 页面事实与客户确认的内容一致，不能把生成初稿直接当成定稿；依赖、配置与凭据分开。

### 5.2 数据与内容迁移

公开网页盘点不抓取或存档会员、订单、预约记录和表单提交。需要私有数据迁移时，先单独确认系统、字段、记录数、权限、敏感性、保存与删除方式，然后使用客户授权的导出/API 或其他批准方式处理，不能交给网页爬虫。

适用项目需要迁移前备份、测试导入、字段及数量核对、必要抽样和客户确认。备份与测试环境同样受访问与保留规则约束。未经明确批准，不把这些数据发送给模型或其他外部工具。

### 5.3 质量验证与客户验收

| 检查维度 | 可验证的验收依据 |
| --- | --- |
| 范围与内容 | 页面/模板/语言/内容条数对照；无占位文字；客户确认事实与授权 |
| 响应式与功能 | 约定浏览器和设备下导航、表单收件、主要行动及集成场景记录 |
| 可访问性 | 自动检查加关键路径人工测试；对比度、焦点、键盘、标签；信息图片适当 alt，装饰图片允许空 alt |
| SEO | 清单内页面元数据、语义、canonical 和索引规则适当；不把单个 H1 数量或固定字符数当排名处罚 |
| 迁移 | URL 处置表逐项核对；相关重定向有效，无链/环；站内链接及适用 sitemap 更新 |
| 实验室性能 | 固定测试页面、设备/网络与工具版本；记录运行方法、目标、前后结果和外部依赖 |
| 真实用户指标 | 独立记录来源与时间窗口；无数据不虚构结果，不以新站缺少数据阻止交付 |
| 安全与部署 | HTTPS、可公开配置、权限与备份责任；不把前台检查当全面漏洞审计 |
| 例外与阻塞 | 写明未完成项、影响与处理责任；偏离已约定验收要求须客户确认 |

不设未经确认的通用 Lighthouse 满分或 Core Web Vitals 保证。项目开始时就把具体条件与目标写入提案；首次验收不能临时新增门槛。第三方脚本影响需要记录和讨论，不自行免除已承诺指标。

### 5.4 生产上线

**前置条件：**范围内验收、客户上线确认、约定付款节点、客户域名/DNS 和部署授权、关键集成权限、回滚方案。

**执行：**

1. 保存必要备份与现状配置；有 DNS 切换时确认窗口、TTL 以及对邮件等现有服务的影响。
2. 发布生产站，验证域名与 HTTPS、关键页面、表单实际收件和约定集成。
3. 核对 URL 处置、canonical、站内链接，以及应公开页面无意外 noindex；保留私密页面的限制。
4. 在包含相关服务且授权可用时完成 Search Console 验证、sitemap 提交、分析配置或 Google 商家资料关联；不保证平台验证/收录完成时间。
5. 记录生产上线日期、已通过检查、待办与回滚条件；客户和负责人确认。

### 5.5 交接、14 天保障与 Care

交接项目代码/资源的约定交付方式、部署信息、账号与续费责任、操作说明和缺陷反馈入口；有 CMS 才提供相应后台培训。域名和账号默认客户持有，通过授权协作；代管情况须明确归属和退出移交。

从双方确认的生产上线日起提供 **14 个自然日**交付缺陷修复保障。期间反馈、经核实属于原交付不符合确认要求的缺陷免费修复，不占 Care 额度，不要求购买 Care；修复完成时间跨期不重新收费。保障不代表全天候值守或固定响应/修复时限。

内容替换、已确认设计后的偏好变化及新增功能按变更或 Care 处理；客户改动或第三方变化引起的问题先查原因，再按约定评估。不把缺陷修复和内容修改混为一类。

Care 可选，现有额度、最低期限、额外费率和不结转条款见[Care 页面](../../app/care/page.tsx)。持续 SEO 单独定范围，不能因为维护中发现机会就自动运行付费分析。

## 6. 付费诊断检查库

仅从本表选取已购买且可验证的项目；报告标注实际覆盖范围。不能把这整张清单当成免费首页体检承诺。

| 维度 | 检查方法与结果边界 |
| --- | --- |
| 性能 | 实验室 LCP/CLS 等与可用真实用户 LCP/INP/CLS 分开；图片、脚本、缓存与字体基于实际取证 |
| 移动端 | 视口、横向溢出、点按、电话/地图/表单；需渲染与人工测试，不能仅凭 viewport 声明判断 |
| SEO | 元数据、语义、范围内 sitemap/robots/canonical/URL 及结构化数据；本地信息只在适用时检查 |
| 可访问性 | 对比度、替代文本、键盘、标签、焦点与标题结构；自动结果不等于完整合规结论 |
| 内容 | 信息时效、事实、服务表达、重复与缺口；客户事实需确认 |
| 转化路径 | 首屏表达、主要行动、信任材料与关键路径；无数据不估算损失或转化提升 |
| 公开安全配置 | HTTPS、混合内容、安全响应头及可验证依赖信息；不据此宣称完整安全 |
| 技术债 | 获授权的代码/平台/备份信息；前台指纹只作为线索，不推断无法确认的版本与后台状况 |

任何模型辅助摘要、分类或草稿，都在付费范围与数据权限内执行，并由人核对证据和事实。问题排序结合用户目标、影响和实施难度，不用虚构营收数字。

## 7. 客户沟通与范围变更

**发现问卷：**业务与客群、目标、现状与已有数据、品牌偏好、素材与授权、技术依赖、语言、时间约束、客户决策与资料责任。

**提案在重度制作前确认：**目标与证据（如已有）、页面与功能清单、交付与不含项、报价及第三方费用、设计与反馈轮次、客户责任、验收、工期、付款节点、迁移风险、账号和数据责任、14 天保障及可选 Care。

付费诊断或已启动项目中，可以补充 before / after、设计方向和原型用于阶段评审；它们不作为免费售前的必备产出。

**变更规则：**书面记录新增需求 → 说明费用/时间/验收影响 → 客户确认 → 执行。素材或反馈延迟后更新排期；不默默扩大范围。内部估时可使用两轮集中反馈作为起点，但对客轮次以已确认提案为准，不把内部假设当成已售承诺。

**风险说明：**内容或 URL 遗失、系统/数据不兼容、集成失效、DNS 与邮件影响、短期搜索波动。按风险设置备份、预演、回滚及复查；不保证具体排名、流量或收入。

## 8. 授权、素材、数据与工具

- 深度采集仅用于已获客户授权的自有站点，记录授权人、日期、域名/路径、范围；遵守访问限制与项目采集预算。
- 付费项目的 robots/sitemap 读取仅用于该阶段。免费首页工具不为复用这套 SOP 而新增请求。
- 竞品仅人工公开页面参考，不自动采集或复制文案、照片、代码、设计资产。
- 存档的客户文案、图片、字体等核对授权；第三方素材不能合法沿用就标注替换。
- 私有迁移数据、测试副本和备份按单独授权处理；资料存档目录不默认存放个人信息。
- 客户资料保留、删除期限与访问权限在提案记录；不默认无限保存。免费扫描及线索采用其独立设计中的最小化与保留规则。
- 营销使用客户名称、截图、before / after 或成果，另取书面许可；案例与界面演示分别标明，不编造已服务客户。

可选工具：HTTP 客户端/解析器、项目授权范围内的 Playwright、Lighthouse/axe、Figma、适合现有平台的开发与部署工具。工具选择由项目条件决定，采用付费服务或外部数据处理前核对预算与权限。本文没有授权采购订阅、自动发布内容或执行客户生产变更。

## 9. 项目归档与最终检查模板

每个项目保存：确认的范围与授权、客户事实与素材清单、范围内盘点、诊断证据、结构与 URL 表、设计及反馈记录、开发与测试结果、变更确认、上线记录、交接和保障期请求。访问权限与保留时间按项目约定设置。

- [ ] 已确认范围、启动款与必要授权；可选步骤有对应购买范围
- [ ] 页面、模板、语言、内容量及集成未超出约定；未覆盖项已说明
- [ ] 旧 URL 各有明确处置；需重定向的目标相关且已测试
- [ ] 业务事实、文案、图片用途与素材权利已确认
- [ ] 约定设备/浏览器关键路径通过，表单验证实际送达
- [ ] 性能条件、数据来源与结果记录完整；无数据不填造指标
- [ ] 可访问性检查包含人工路径；装饰图片 alt 处理正确
- [ ] 应公开页面无意外 noindex；私密与预览限制得到保留
- [ ] 适用的内容/数据迁移、备份与恢复检查通过
- [ ] 生产发布与回滚方案、客户上线确认及付款条件满足
- [ ] 账号、续费、资料保留/删除和交接责任已记录
- [ ] 14 天保障起点与反馈入口明确；Care 为单独可选服务
- [ ] 营销展示如需使用客户资料，已有独立书面许可

模板按项目记录结果，不在本文填写客户状态。原草稿的套餐页数/周期和泛化“全站达标”表不再作为标准承诺；现有套餐以[服务定义](../website-standard-service.md)引用的官网范围为基线。
