# Northline 首页 SEO 基础体检 — 最终设计 v1.0

状态：产品设计定稿；本次不实现功能。它取代此前 PDF 中“免费阶段运行全站、竞品与多平台 AI 采集”的首版范围，不改变 Northline Studio 的其他业务。

## 1. 定位和成功标准

这是 Northline Studio SEO 服务的免费入口。用户提交一个公开首页，系统通过确定性规则返回一份短而可信的基础检查结果，再由用户自主联系 Northline。免费阶段不需要逐单人工调研。

首版成功意味着：用户能完成检查、看懂一两个真实发现，并在有需求时带着检查上下文发起咨询。它不是完整搜索表现评估，也不是独立的订阅 SaaS。

## 2. 已确定的产品决定

- 属于 Northline Studio，入口在现有 /seo 页面。
- 免费阶段只检查用户指定的一个首页 HTML 响应及其响应头；不跟随站内链接、不下载图片或脚本。
- 不使用 LLM，不调用付费搜索、商家资料或排名 API。
- 免费结果不要求注册、姓名、邮箱或电话。
- 最多展示两条有依据的优先发现；没有问题就如实说明，不凑数。
- 深入分析在确认客户需求后另行启动；联系表单不会自动触发昂贵采集。
- 深入模块可以用带锁的样例预览，但必须说明尚未运行。
- 首版不提供自助购买完整版、账号系统、订阅、自动改站、PDF 生成或自动邮件报告。
- 联系请求会自动携带扫描上下文，避免重新收集基础信息。

本设计建议首版不展示一个加权 SEO 总分：用检查范围、完成情况和真实发现建立可信度。这是本次定稿的产品判断；若以后增加分数，必须另行定义和校准“首页基础检查分”，不能称为全站 SEO 分。

## 3. 考虑过的方案

| 方案 | 优点 | 代价 | 决定 |
|---|---|---|---|
| 提交网址后直接运行完整调研 | 第一次就有丰富结果 | 免费用户消耗模型、搜索和浏览器资源；首版交付面过大 | 不作为首版 |
| 全部结果放到强制留资后 | 容易收集联系方式 | 用户看不到真实价值就需要提供资料；不是已经选定的体验 | 不采用 |
| 免费首页规则检查，确认需求后深入分析 | 成本可控、自动运行，用户先获得价值 | 首版不能展示真实排名、竞品和 AI 可见度 | 采用 |

该选择来自最后几轮讨论。具体超时、缓存和限流数字是实现起点，由下文单独标明；不是用户指定的业务承诺。

## 4. 用户流程和页面结构

整个免费流程留在 /seo 页面，保持现有暖白、蓝色、绿色视觉风格和清楚的服务分区。保留其他服务页面及导航。

### A. 输入

首屏主文案：
“检查你的网站首页，发现值得先改善的地方。”

辅助文案：
“免费查看基础检查结果，无需注册或填写电话。检查公开 HTML 和响应信息，不代表完整 SEO 审计。”

输入仅包括网址；报告语言跟随界面选择，默认英文，可切换中文。按钮：“免费检查首页”。

从 title、og:site_name、结构化数据中提取的站点名称仅用于展示。识别不出名称时使用域名，不调用模型推断业务。首版没有行业确认、地点、关键词或竞品步骤。

### B. 检查中

按钮禁用并显示“正在检查你提交的页面…”。不展示伪造百分比、倒计时或虚构的逐阶段完成状态。一个请求完成后直接展示结果；允许用户在失败后修改网址重试。

### C. 免费结果

结果区有四块：
1. 检查概况：实际检查地址、最终跳转地址（如不同）、检查时间、是否复用缓存，以及已完成/无法判断/不适用项目数。
2. 最多两条重点发现：实际观察、证据片段、适用条件、简短说明和固定模板建议。
3. 已通过的基础项摘要；不要求用户展开大量技术文字。
4. 深入分析预览与联系入口。

结果不会显示未经验证的流量、排名、收入损失、获客预测、竞品成绩或 AI 提及率。

当结果来自缓存时，明确显示原始检查时间，不声称刚刚重新扫描。

### D. 深入分析预览

只显示三个交付方向：
- 其他重要页面的检查；
- 内容与搜索机会；
- 按优先级排列的改进方案。

说明必须可见：“以上为深入分析的交付示例。尚未针对你的网站运行；确认需求后启动。”

可以使用带锁或模糊的示例卡片，但不能生成虚假的客户分数、发现数量、竞品名单或“你的完整版已完成”提示。完整内容不能被加载到客户端后仅靠 CSS 隐藏。

主按钮：“让 Northline 帮我进一步分析”。可提供“了解深入分析”链接，仍导向同一联系流程。

## 5. 自动检测规则

先验证页面能否正常取得：URL 可用、响应为可处理的 HTML，且内容完整。页面取得失败不是 SEO 失败。

首版规则如下；它们评估本次响应中的基础信号，不证明 Google 已抓取或收录。

| 规则 | 读取内容 | 允许的输出 |
|---|---|---|
| HTTPS | 实际请求及跳转后的协议 | 说明最终访问是否使用 HTTPS；不声称完成全部 TLS 安全审计 |
| 页面标题 | title 文本 | 非空为已发现；缺失或明显占位标题可提示确认。不把 60 字符作为硬性扣分线 |
| 描述信息 | meta description | 存在为已发现；缺失给补充建议，同时说明搜索引擎可能自行生成摘要 |
| 主标题 | 原始 HTML 中 h1 | 说明是否发现及数量；缺失或多个只作结构建议，不宣称排名处罚 |
| 索引限制 | meta robots、X-Robots-Tag | 如发现 noindex，提示“若希望此首页被收录，请确认此设置”。未发现不等于已收录 |
| canonical | canonical 链接 | 检查已提供值的语法与目标域名关系；缺失或跨域只作需确认的信号，不声称目标页面失效 |
| viewport | viewport 声明 | 只报告是否声明，不据此断言完整移动端可用性 |
| 图片替代文本 | img 的 alt 属性及明确装饰标记 | 可提示缺少 alt 属性的图片；空 alt、明确隐藏/装饰用途不自动当错误；没有图片为不适用 |

明确不检查：robots.txt 文件、sitemap 文件、其他页面状态、页面真实渲染、Lighthouse、Core Web Vitals、真实收录、GA4/GSC 配置、GBP、竞争对手、搜索词排名和 AI 推荐。

JavaScript 渲染站点：如果主要内容未出现在初始 HTML，报告说明“本次未执行 JavaScript”。不能把未取得的动态内容称为网站缺失；相应检查标记为无法判断。实现需优先避免误报，而不是保证每个站都能出两条发现。

## 6. 结果状态和发现选择

规则状态为：已发现/通过、需确认、无法判断、不适用。只在证据支持且条件明确时提出建议。

展示顺序由版本化规则决定，例如：意外的索引限制、无法正常公开访问、标题问题，再到描述或结构建议。索引限制是否为问题必须写出“若希望公开收录”的条件。

每条发现必须包含：
- 规则编号和版本；
- 对应 URL；
- 实际观察值或经过转义的短证据片段；
- 检查时间；
- 为什么值得确认；
- 一到两步固定模板建议。

最多展示两条，少于两条照实显示。没有发现时：
“本次已完成的基础检查中，未发现需要优先提示的问题。其他页面、搜索表现和未检测项目仍需另行分析。”

未知或不适用不得写成失败，也不能隐藏检查范围造成“全部正常”的印象。

## 7. 联系流程

点击报告中的合作按钮后，在当前页面展开或进入带 audit 引用的联系表单。

必填：
- 姓名；
- 邮箱；
- 想改善什么（短文本）。

电话选填，不要求拆成 first name/last name。网址、检查编号和已展示结果自动携带，不让用户重复填写。不默认勾选营销订阅。

提交后只有在请求成功保存时才显示“已收到你的需求”。持久化失败时明确提示未提交，并保留已填内容供重试。提供现有邮箱 northlinestudio425@gmail.com 作为可见备用入口。

联系记录保存一份扫描摘要快照，包含检查时间和规则版本。扫描缓存过期后，这份联系记录仍可解释当时客户看到了什么。

Northline 接收合作需求通知；通知失败不能丢失已入库请求，应记录待补发并可重试。通过请求唯一标识避免双击造成重复线索和通知。

收集联系方式仅用于处理请求及相关沟通；后续营销须另外征得同意。发送表单不代表购买、同意报价或授权未来的模型/第三方分析。

后续深入报告、报价、交付和执行流程是下一阶段的单独范围，本次不构建“联系后自动运行完整版”的后台。

## 8. 技术边界

前端继续使用现有 React/vinext 静态导出网站和 Vercel 托管，不为此改造整个站点架构。

新增一个轻量 TypeScript 服务接口。首选与现有 Vercel 部署兼容的 Node 服务入口，使用标准 HTTP 客户端和 HTML 解析器；不引入浏览器、LLM、任务集群或复杂工作流。

实施计划负责确认实际部署适配、可用的持久化存储和邮件服务。选择属于实现者的技术决定，约束是：适合低流量、可限额、低固定成本、不默认购买付费套餐，并能实现下述持久化和重试合同。不得假设当前静态站已经拥有可用 API 或数据库。

API 合同：
- POST /api/seo-check，输入 URL、locale 和请求标识；返回状态、扫描引用、实际 URL、时间、缓存标识、覆盖情况和最多两条发现。
- POST /api/seo-inquiries，输入扫描引用、姓名、邮箱、目标、可选电话和提交唯一标识；返回已保存的请求编号。

两个入口可按实际部署映射到同源路径；允许跨源时使用确切的 Northline origin 白名单。CORS 本身不作为认证、防刷或 SSRF 保护。

没有客户端账户系统，也没有公开的线索列表接口。缓存、线索和运维访问必须隔离，扫描响应不得带出联系方式。

## 9. 成本控制与请求安全

免费扫描没有 LLM token 和付费检测数据 API 费用。托管、网络、存储及合作通知邮件仍可能有费用，不能宣传绝对零成本。

建议的初始运行参数：
- 每次只取得一个首页响应，最多跟随 3 次跳转；
- 总超时 12 秒，解压后 HTML 最大 1 MiB；
- 同一规范化 URL、规则版本的成功扫描缓存 24 小时；
- 失败仅短时缓存，避免把临时问题长期固化；
- 每 IP 每小时最多 5 次新扫描，缓存命中可使用更宽限额；
- 全局每日新扫描上限为部署配置，达到上限后拒绝新任务并说明稍后重试；
- 扫描记录初始保留 7 天，联系记录保留 90 天后按配置删除；用户删除请求有处理入口。

这些是可配置的实现起点，需在测试中校准，不是固定的用户服务承诺。缓存键不得只使用域名，以免子目录部署的网站互相混淆；语言不同可以复用事实但分别渲染文案。

只接受公开 HTTP/HTTPS 页面，允许子目录部署的首页。缺少协议时默认 HTTPS；去掉 fragment，并把实际检查地址显示给用户。不擅自把子目录主页改成域名根路径。拒绝 URL 凭据、非 80/443 端口、内网/回环/链路本地/云元数据等目标。初始请求及每次重定向都要检查解析结果，防范 IPv4/IPv6 和 DNS 重绑定；实际连接也必须受约束，不能只做字符串校验。

不获取客户 cookie、账号凭据或私有页面。不绕过登录、验证码、访问挑战或明确的访问限制。

不持久化完整 HTML；只保存规则结果、必要的短证据和时间/版本。所有页面文字和 URL 都作为不可信输入进行转义，不能插入为活动 HTML。

## 10. 错误体验

| 情况 | 展示 |
|---|---|
| URL 无效/不允许访问 | 指出需要公开网页地址；不创建 SEO 结论 |
| 超时、TLS 或网络错误 | “暂时无法读取该页面”，可重试或联系 |
| 403、429、挑战页或登录页 | “该页面限制了本次访问”，不扣分、不绕过 |
| 非 HTML/文件过大 | 说明本次工具范围；保留可靠的响应信息，其余为无法判断 |
| 主要内容依赖 JavaScript | 明确未执行脚本，相关项未知 |
| 规则只完成一部分 | 交付可靠的局部发现，并显示缺失范围 |
| 服务额度已用完 | 说明暂不可检查，保留联系入口 |
| 联系保存失败 | 不显示提交成功，不清空表单，显示备用邮箱 |

不承诺固定 30 秒/60 秒完成，不用动画模拟已经执行的工作。

## 11. 数据与实现者责任

最小数据合同：
- scan：不可预测的引用、规范化/最终 URL、时间、规则版本、运行状态、检查项、已展示发现、缓存期限；
- inquiry：请求编号、扫描引用、摘要快照、姓名、邮箱、目标、可选电话、创建/删除时间；
- notification：联系请求编号、通知状态、重试次数、下次尝试时间。

实现计划自行选择 SQL/KV 等存储适配、解析库、运行时版本和邮件供应商；确保通知重试与联系记录可靠，不需要为免费扫描引入大队列。扫描引用不提供访问其他客户信息的能力。

开发前需要确认运行环境、数据持久化和通知凭据；凭据不可写入仓库。未配置的服务不能用演示成功状态代替。

## 12. 首版验收

1. 用户只提交网址即可看到真实结果；姓名/邮箱/电话不会挡住免费报告。
2. 运行与依赖清单中没有 LLM、付费搜索或 Places 调用；没有浏览器执行及站内页面爬取。
3. 已知样例能正确识别协议、标题、描述、h1、noindex、canonical、viewport 和图片 alt 的适用状态。
4. 空 alt、无图片、子目录主页、JS 主内容、无 canonical 等情况不会被机械地判为 SEO 失败。
5. 每条展示发现都能回到 URL、观察值、时间和规则版本；没有发现时不造问题。
6. 错误、限流、缓存、超大响应及重定向按合同处理；缓存命中不伪装成新检查。
7. 公共地址校验覆盖重定向、IPv6 和实际连接；不允许读取内部资源。
8. 联系请求与正确的扫描快照绑定；重复提交不重复创建或发送通知。
9. 保存失败与通知失败可区分；不会把未保存的联系请求显示为成功。
10. 在桌面和手机检查输入、加载、结果、锁定预览、联系成功/失败，以及键盘和屏幕阅读器体验。
11. 不出现全站分数、真实排名、AI 推荐结果、虚假完整版或未承诺的收费。
12. 现有 Northline 导航、服务价格、条款和其他页面保持可用。

上线前用覆盖上述边界的样例校准规则；日常客户报告仍由系统自动完成。

## 13. 衡量与后续

首版关注：提交率、成功/部分完成率、耗时、缓存命中、扫描成本、结果后的联系点击率和成功提交率。它们是待验证指标，不预设虚构的转化收益。

后续可另立设计：更多页面、正式评分、GSC/分析授权、竞品、AI 可见度、PDF、一次性付费报告和长期监测。只有经过明确的范围、触发条件和预算确认才加入，不由免费提交或联系表单暗中触发。

本设计唯一的首版主线：
输入网址 → 免费首页规则体检 → 真实发现 → 自愿联系 Northline → 确认需求后开展后续服务。
