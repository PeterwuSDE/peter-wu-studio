## 两条服务线对比

| 维度 | Modernization（改版） | 从零建站（新站） |
| --- | --- | --- |
| 适合对象 | 已有网站但老旧、慢、手机端差或难更新的本地商家 | 还没有网站的门店或本地商家 |
| 入口 | 一个现有网址 | 商家名称与地址，加一次需求访谈 |
| 数据来源 | 自动抓取现有站点的全部内容与结构 | 访谈与问卷、公开信息（Google 商家资料与地图、点评、社交账号）、商家提供的菜单与价目表、同城竞品参考 |
| 重点 | 诊断问题、保住 SEO 资产、重做 IA 与设计 | 建立定位与品牌、撰写内容、从零设计与开发、打通本地入口 |
| 主要风险 | URL 变更与 SEO 流失、数据迁移、功能集成 | 素材与内容不足、商家决策与资料提供延迟、信息核实、版权与授权 |
| 周期估计 | 约 1 到 12 周，随档位而定（待确认） | 约 1 到 14 周，随档位而定（待确认） |
| 上线后 | 可衔接 ongoing care | 可衔接 ongoing care |

两条线共享信息架构、设计、原型、开发、上线与 ongoing care 的方法；差异集中在入口与前期资料来源。

## Modernization 服务定位

Northline Studio 官网把「Websites & modernization」列为核心服务之一，覆盖新建、改版与迁移，并有 ongoing care（托管、监控、维护与约定的修改额度）作为上线后的衔接。本服务把「改版现有网站」做成一套可重复的流程：输入一个网址，输出一套现代化方案和原型。

| 适合的本地商家信号 | 典型表现 |
| --- | --- |
| 网站老旧 | 视觉停留在多年前，信息过时，品牌与线下门店不一致 |
| 手机端体验差 | 需要缩放、按钮太小、电话和地址不能一键使用 |
| 加载慢 | 图片未压缩、脚本过多、移动端首屏等待久 |
| 搜索可见度低 | 标题与描述缺失或重复、没有本地搜索相关页面、结构混乱 |
| 无法自己更新 | 依赖开发者改文字，或后台难用，营业时间和活动信息长期不更新 |
| 转化低 | 预约、致电、到店路径不清晰，行动按钮不突出 |

## Modernization 工作流总览（URL 驱动）

1 输入网址 → 2 抓取与盘点 → 3 现状诊断 → 4 新信息架构 → 5 设计方案 → 6 原型生成 → 7 交付与提案

| 步骤 | 主要产出 | 自动化程度 | 人工审核重点 |
| --- | --- | --- | --- |
| 1 输入 | 项目简表、授权记录 | 中 | 授权与目标确认 |
| 2 抓取盘点 | 内容盘点表、站点地图、文案与图片存档 | 高 | 关键事实核对 |
| 3 现状诊断 | 诊断报告与优先级清单 | 中高 | 视觉与转化判断、业务翻译 |
| 4 新 IA | 新站点地图、URL 映射表 | 中 | 保留与删除决策 |
| 5 设计方案 | 设计方向、令牌、组件、高保真稿 | 低 | 全部审美与品牌决策 |

| 7 交付提案 | 提案文档、before / after 对比 | 中 | 沟通、范围确认、报价 |

## Modernization 步骤 1：输入（网址）

确认授权与范围，把一个网址变成一个可立项的任务。

**输入**

门店或本地商家的网站 URL；确认该站属于客户或已授权的潜在客户；如有，提供 CMS 后台、Google Analytics、Search Console 的只读权限（可选）。

**产出与交付物**

项目简表：域名、站点类型（展示站 / 预约 / 电商 / 其他）、业务类型、所在城市、目标（获客 / 预约 / 到店 / 线上销售）、授权状态记录。

**我们的工具与方法**

内部项目表单（Notion / 表格，待确认）；域名 WHOIS 与技术栈识别（如 Wappalyzer、BuiltWith 类工具）；一次性读取 robots.txt 与 sitemap.xml。

**质量检查**

授权已确认；域名可访问；站点规模初判（约多少页）；已识别是否有登录区、预约系统、支付等不适合自动抓取的部分。

**自动化部分**

域名可达性检查、技术栈识别、robots.txt 与 sitemap.xml 读取、规模初判。

**需人工审核**

授权与合规确认；与客户确认业务目标和不可更改项（品牌色、Logo、法务文案等）。

## Modernization 步骤 2：自动抓取与内容盘点

把现有站点的全部内容和结构变成结构化数据，作为后续所有步骤的事实来源。

**输入**

步骤 1 的项目简表与域名；robots.txt 规则；抓取深度与速率上限。

**产出与交付物**

内容盘点表（每页一行：URL、标题、H1、元描述、正文字数、模板类型、内链数、图片数、状态码）；站点地图与导航树；全站文案存档（Markdown / JSON）；图片与媒体清单（含 alt、尺寸、体积）；联系信息、营业时间、地址、服务与价格栏目（如有）、表单与第三方嵌入清单；首页与关键页面的桌面与手机截图。

**我们的工具与方法**

无头浏览器抓取（Playwright 等，渲染 JS 页面）；站点地图解析；HTML 转 Markdown；图片下载与元数据提取；结构化数据（Schema.org / JSON-LD）提取。具体框架 待确认。

**质量检查**

抓取页数与 sitemap.xml 和内链发现的页数对账；状态码异常（404、重定向链）已列出；无遗漏的导航项；联系信息与站点前台显示一致；抓取遵守速率限制与 robots 规则。

**自动化部分**

全站爬取、字段提取、截图、图片与链接清单、重复与缺失元数据标记。

**需人工审核**

核对联系信息、服务项目、营业时间等关键事实；标注哪些内容是过期或不能沿用的；标记需要客户提供的缺失素材。

## Modernization 步骤 3：现状诊断

用数据说明现有站点哪里有问题、影响多大、先改什么。

**输入**

内容盘点表、截图；性能测试结果；客户目标与行业竞品（可选 2 到 3 个）。

**产出与交付物**

诊断报告（含评分摘要）：信息架构与导航、视觉与品牌一致性、性能（Core Web Vitals）、SEO 基础、移动端、可访问性、转化路径、安全与技术债；问题清单按影响和修复难度排序；一页纸摘要用于对客户沟通。

**我们的工具与方法**

Lighthouse / PageSpeed Insights；Core Web Vitals 实测数据（如可得）；axe 等可访问性检测；SEO 爬取与元数据检查；安全头与 HTTPS 检查；人工走查移动端关键路径（打电话、导航、预约、下单）。详见下方诊断审计清单。

**质量检查**

每条问题都有证据（截图 / 指标 / URL）；评分口径固定；高优先级问题已与转化目标挂钩；不使用未验证的数据做效果承诺。

**自动化部分**

性能、SEO、可访问性、安全检测与评分；问题归类与初排序。

**需人工审核**

视觉与品牌判断；转化路径评估；把技术问题翻译成客户能听懂的业务影响；最终优先级排序。

## Modernization 步骤 4：新信息架构

在保住现有 SEO 资产的前提下，重新设计站点结构，让访客更快找到所需信息。

**输入**

内容盘点表、诊断报告、客户目标与目标客群、关键词与本地搜索意图（如可得）。

**产出与交付物**

新站点地图（保留 / 合并 / 删除 / 新增 标注）；新旧 URL 映射表与 301 重定向清单；主导航与页脚结构；每个页面类型的区块清单（线框级）；内容缺口清单与文案建议；本地 SEO 页面规划（服务页、地区页，视业务而定）。

**我们的工具与方法**

内容盘点表驱动的分组与聚类（可用大模型辅助归类）；站点地图可视化（Diagram / Whimsical / FigJam 类，待确认）；关键词研究工具（待确认）；线框工具（Figma 等，待确认）。

**质量检查**

每个旧 URL 都有去向（保留、重定向或明确下线）；任何关键业务页面在导航两次点击内可达；每页只有一个主要行动；命名与客户用语一致。

**自动化部分**

旧页面聚类与结构建议初稿、URL 映射表初稿、重复内容与空洞页标记。

**需人工审核**

确认保留与删除决定；确定导航命名与优先级；客户审批新站点地图。

## Modernization 步骤 5：现代化设计方案

给出一套可落地的视觉方向和组件规范，兼顾品牌延续与现代感。

**输入**

新信息架构、现有品牌资产（Logo、色彩、字体、照片）、客户喜好与参考站点、行业惯例。

**产出与交付物**

设计方向说明（情绪板、2 个方向供选）；排版（字体、字号层级、行距）；配色（主色、辅色、中性色、对比度检查）；栅格与间距；核心组件库（按钮、卡片、表单、导航、预约入口、评价、地图与营业时间）；首页与 1 到 2 个关键页面的高保真稿（移动端优先）。

**我们的工具与方法**

Figma（设计稿与组件）；设计令牌（颜色、字号、间距）；对比度与可访问性检查；AI 辅助生成情绪板与方向探索（须人工把关，避免千篇一律）。

**质量检查**

移动端优先；文字对比度符合 WCAG AA；品牌元素延续或有明确的升级理由；组件可复用、命名一致；设计与 IA 的每个页面类型一一对应。

**自动化部分**

设计令牌草案、配色与对比度校验、组件清单生成。

**需人工审核**

全部审美与品牌决策；方向选择；与客户评审并锁定方案。

## Modernization 步骤 6：原型 / 页面生成

把设计方案变成可点击、可访问的现代化原型，至少做出首页。

**输入**

新信息架构、设计方案与令牌、步骤 2 的文案与图片资产（经审阅）、客户补充的素材。

**产出与交付物**

可在线预览的首页原型（响应式，含真实文案与图片）；视情况扩展到关键页面（服务页、联系页）；预览链接；与旧站并排的 before / after 截图。

**我们的工具与方法**

静态站或轻量框架（如 Astro / Next.js + Tailwind，待确认）；设计令牌转 CSS 变量；AI 辅助生成页面代码并人工重构；图片压缩与响应式格式（WebP / AVIF）；预览托管（如 Vercel / Netlify，待确认）。

**质量检查**

移动端与桌面端截图对比；Lighthouse 性能、可访问性、SEO 得分达到内部目标（具体阈值 待确认）；所有链接和表单可用；文案与盘点事实一致；无占位文字残留。

**自动化部分**

页面脚手架与区块代码生成、图片优化、构建与预览部署、自动化 Lighthouse 检测。

**需人工审核**

代码审查；视觉还原验收；文案与事实核对；交互与表单测试。

## Modernization 步骤 7：交付与客户提案

用 before / after 对比让客户直观看到价值，并推动下一步决定。

**输入**

诊断报告、新 IA、设计方案、原型与对比截图；客户沟通记录。

**产出与交付物**

客户提案文档（现状、问题、方案、before / after、范围与时间线、风险、下一步）；诊断一页纸；对比图（可用于营销，须经客户同意）；迁移计划与重定向清单；如客户继续，转入正式开发上线与 ongoing care 维护服务。

**我们的工具与方法**

提案模板；截图对比工具；演示链接；项目管理工具（待确认）。

**质量检查**

所有结论都有证据；不含价格（客户询价时另行报价）；范围与不含项写清；迁移风险已披露；营销用的对比图已获客户书面同意。

**自动化部分**

提案初稿、对比截图拼图、报告导出。

**需人工审核**

提案讲解与沟通；范围与时间线确认；报价（人工、按询价提供）；营销授权确认。

| 步骤 | 主要产出 | 自动化程度 | 人工审核重点 |

| 1 需求访谈 | 项目简报、资料与授权清单 | 中 | 访谈与事实确认 |
| 2 公开信息与竞品 | 公开信息盘点、竞品参考表、关键词清单 | 高 | 来源、口碑与授权判断 |
| 3 品牌与定位 | 定位陈述、轻量品牌套件 | 低 | 定位与审美决策 |
| 4 内容撰写 | 页面文案、拍摄方案 | 中 | 事实核对与文案审校 |
| 5 信息架构 | 站点地图、线框级区块 | 中 | 页面取舍与命名 |
| 6 设计 | 设计方向、令牌、高保真稿 | 低 | 全部审美决策 |
| 7 原型 | 可预览原型 | 中高 | 视觉验收 |
| 8 开发 | 完整站点与集成 | 中高 | 代码审查与功能测试 |
| 9 上线 | 域名、托管、Google 商家关联、基础本地 SEO | 中 | DNS 切换与商家验证 |
| 10 交接与 care | 交接文档、培训、care 方案 | 中 | 培训与沟通 |

## 从零建站 步骤 1：需求访谈与问卷

没有网站可抓取时，用访谈和问卷把商家的业务、客群与目标变成结构化项目简报。

**输入**

商家负责人访谈（线上或到店，时长待确认）；发现问卷；线下已有资料（菜单、价目表、宣传单、Logo、门店与产品照片）；基础营业信息（名称、地址、电话、营业时间）。

**产出与交付物**

项目简报（业务、目标客群、差异点、目标、约束、不可更改项）；资料清单（已有 / 缺失 / 责任人与期限）；账号与授权清单（Google 商家资料、社交账号、域名、托管）。

**我们的工具与方法**

在线问卷（工具待确认）；访谈提纲模板；访谈录音转写（须事先征得同意）；大模型把访谈与问卷整理成简报初稿。

**质量检查**

目标可衡量（致电、预约、到店、线上下单）；名称、地址、电话、营业时间、服务项目经商家书面确认；每项缺失资料都有责任人与期限。

**自动化部分**

问卷分发与汇总、录音转写、简报初稿、资料清单生成。

**需人工审核**

访谈本身；判断商家真实优势与客群；确认全部关键事实。

## 从零建站 步骤 2：公开信息收集与竞品参考

用商家已有的公开线上足迹和同城同行业竞品，补足事实、素材与方向，替代原来的网站抓取。

**输入**

商家名称与地址；商家提供或授权的 Google 商家资料、地图页面、Instagram、小红书等社交账号链接；菜单、价目表等商家提供的资料；同城同行业竞品网站清单（我们筛选，商家过目）。

**产出与交付物**

公开信息盘点表（Google 商家资料与地图信息、点评与高频关键词、社交账号内容主题与可用素材清单、菜单与价目表的结构化整理）；竞品参考表（结构、页面类型、转化路径、视觉特点、优缺点）；本地搜索意图与关键词清单。

**我们的工具与方法**

优先使用官方渠道与商家授权（Google 商家资料访问或商家导出，具体接口待确认）；社交账号内容由商家导出或授权，不绕过登录抓取；菜单与价目表用 OCR 整理为表格；竞品站只读分析，复用 Modernization 的盘点与 Lighthouse 检测；关键词工具待确认。

**质量检查**

每条信息标注来源与日期；点评与社交内容不直接复制进网站，使用客户照片、点评原文或第三方素材需另行取得许可；信息与商家确认一致；竞品只用作结构与方向参考，不复制文案、图片或代码。

**自动化部分**

公开资料汇总、点评关键词归纳、菜单 OCR、竞品页面盘点与性能检测。

**需人工审核**

筛选竞品；判断口碑与点评的真实情况；剔除不适合公开的内容；与商家确认。

## 从零建站 步骤 3：品牌与定位

明确门店为谁、提供什么、与同城同行有何不同；没有品牌资产时，做一套够用的轻量品牌套件。

**输入**

项目简报、公开信息盘点、竞品参考表、商家已有 Logo 或色彩（如有）。

**产出与交付物**

定位陈述（为谁、解决什么、差异点）；语气与用语指南；轻量品牌套件（字标或 Logo 方案、主辅色、字体搭配、图片风格、基础使用规则）；已有品牌资产时则做整理与补全。

**我们的工具与方法**

Figma；配色与对比度检查；AI 辅助探索方向（须人工把关，避免与竞品雷同）；名称与商标做初步公开检索，仅作提示，由商家自行确认，不作法律结论。

**质量检查**

小尺寸与手机屏幕上可辨识；文字对比度符合 WCAG AA；可延展到门店招牌与线下物料；与同城竞品有区分度。

**自动化部分**

配色与字体候选、对比度检查、方向草图。

**需人工审核**

定位决策；Logo 与审美决策；商家确认。

## 从零建站 步骤 4：内容撰写

在设计之前把文案和图片准备好，避免用占位内容做设计。

**输入**

项目简报、定位与语气指南、公开信息盘点、商家提供的资料与照片。

**产出与交付物**

各页面文案（首页、关于、服务或菜单、联系、常见问题等）；标题与元描述；图片与拍摄方案（镜头清单、场景、尺寸、拍摄时间建议，或图库与授权说明）；Google 商家资料文案建议；内容缺口与待客户提供清单。

**我们的工具与方法**

文案模板；大模型起草初稿（必须人工改写并核对事实）；拍摄清单模板；图片压缩与命名规范。

**质量检查**

事实与商家确认一致；无夸大或无法证实的承诺；每页有一个主要行动；图片授权清楚（自拍、客户提供或购买授权）；语气符合指南。

**自动化部分**

文案初稿、元数据初稿、拍摄清单生成。

**需人工审核**

全部文案审校与事实核对；照片筛选或拍摄；商家审批。

## 从零建站 步骤 5：信息架构

为新站规划少而精的结构，让访客快速找到电话、地址、服务与预约入口。

**输入**

项目简报、内容、竞品参考表、本地关键词清单。

**产出与交付物**

站点地图与层级；主导航与页脚；各页面类型的区块清单（线框级）；本地 SEO 页面规划（服务页、地区页，视业务而定）；URL 规划。

**我们的工具与方法**

与 Modernization 步骤 4 相同的站点地图与线框工具（待确认）；关键词工具（待确认）。

**质量检查**

关键业务页面两次点击内可达；每页只有一个主要行动；URL 简短稳定；命名用客户的用语；没有为凑数而加的页面。

**自动化部分**

结构建议初稿、URL 命名建议。

**需人工审核**

页面取舍；导航命名；商家审批。

## 从零建站 步骤 6：设计方案

在新品牌套件基础上给出视觉方向和组件规范，移动端优先。

新信息架构、品牌套件、定稿文案与图片。

**产出与交付物**

与 Modernization 步骤 5 相同：设计方向、排版与配色、设计令牌、核心组件、首页与 1 到 2 个关键页面的高保真稿。

**我们的工具与方法**

Figma；设计令牌；对比度与可访问性检查；AI 辅助探索（人工把关）。

**质量检查**

移动端优先；对比度符合 WCAG AA；设计与品牌套件一致；组件可复用；设计页面与 IA 一一对应；使用真实文案而非占位文字。

**自动化部分**

设计令牌草案、对比度校验、组件清单生成。

**需人工审核**

全部审美与品牌决策；方向选择；与商家评审并锁定。

## 从零建站 步骤 7：原型

把设计变成可点击的原型，让商家在开发前看到并确认。

**输入**

确认的设计方案、定稿文案与图片。

**产出与交付物**

可在线预览的首页与关键页面原型（响应式）；预览链接；设计到原型的差异清单。没有旧站，因此没有 before / after，可用与同城竞品的并排对比作为内部参考。

**我们的工具与方法**

**质量检查**

移动端与桌面端截图核对；链接与表单可用；Lighthouse 达到内部目标（阈值待确认）；文案与商家确认一致；无占位文字残留。

**自动化部分**

页面脚手架与区块代码、图片优化、预览部署、Lighthouse 检测。

**需人工审核**

代码审查；视觉还原验收；商家评审与确认。

## 从零建站 步骤 8：开发

把确认的原型做成完整、快速、商家能自己更新的网站。

**我们的工具与方法**

**质量检查**

内部性能与可访问性阈值达标（待确认）；所有表单、预约与链接测试通过；主流浏览器与手机测试；让商家演练一次自行更新内容。

**自动化部分**

脚手架、构建、预览部署、自动化检测。

**需人工审核**

代码审查；功能与内容测试；商家验收。

## 从零建站 步骤 9：上线

**输入**

**我们的工具与方法**

**自动化部分**

## 抓取合规与版权

> **原则**
>
> 自动抓取只用于客户或已明确授权的潜在客户自己的网站。不抓取竞品或第三方网站的内容用于复用；竞品只做公开页面的人工参考，不复制文案、图片或代码。

- 开始前确认授权，并记录谁在何时授权；潜在客户场景下建议先取得邮件确认（流程待确认）。
- 读取并遵守 robots.txt；设置较低的请求速率与并发，避免影响客户站点；避开登录区、后台与含个人数据的页面。
- 只存档客户拥有或有权使用的文案与图片；第三方素材（图库照片、字体、插件）需核对授权，不能沿用就在盘点表中标注并替换。
- 客户个人信息（会员、订单、表单提交）不抓取、不存档。
- 将客户的 before / after 对比用于营销前，需取得客户书面同意。
- 抓取数据的保存期限与删除方式写入合同或提案（具体条款待确认，建议由法务把关）。
- 从零建站：公开信息只收集商家自己的 Google 商家资料、社交账号与商家提供的资料，且须取得商家同意；遵守各平台使用条款，不绕过登录、不批量抓取他人账号。
- 从零建站：点评原文、社交帖子与照片的版权归原作者或平台，使用前需取得许可；同城竞品网站只做只读参考，不复制其文案、图片、代码或设计。
- 从零建站：公开点评与社交内容中的顾客个人信息不收集、不存档。

## 客户沟通物料

### 发现问卷要点

- 业务：主营服务、主要客群、最赚钱与最想增加的服务、服务区域。
- 目标：希望网站带来什么（电话、预约、到店、线上下单），如何衡量。
- 现状：目前的痛点、已有数据（流量、来电、预约量）、谁在维护网站。
- 品牌：Logo 与色彩是否固定、喜欢与不喜欢的网站、语气偏好。
- 素材：照片、视频、评价、认证与奖项、可公开的案例。
- 技术：域名与 DNS 在哪、托管与 CMS、第三方系统（预约、支付、邮件）。
- 约束：上线时间节点、合规要求、必须保留的页面与功能。

### 提案结构

1. 背景与目标
2. 现状诊断摘要（带证据）
3. 建议方案：新 IA、设计方向、原型预览
4. Before / after 对比
5. 服务档位与交付物、不含项
6. 时间线与客户配合事项
7. 迁移风险与应对
8. 上线后支持（ongoing care 选项）
9. 下一步与确认方式（价格按询价单独提供）

### 变更范围控制规则（草案）

- 提案与合同写明页面数、设计轮次、交付物与不含项，以此为范围基线。
- 设计稿与原型各设固定评审轮次（建议 2 轮，待确认），超出部分按变更处理。
- 所有变更需书面提出，评估对范围与时间的影响，客户确认后再执行。
- 内容由客户提供的，设定提交期限；逾期则时间线顺延。
- 上线后的小修改走 ongoing care 的修改额度，不属于项目范围。

### 迁移风险说明

| 风险 | 说明 | 我们的措施 |
| --- | --- | --- |
| URL 变更与重定向 | 旧链接失效会损失搜索流量和外部链接 | 建立新旧 URL 映射，上线时统一配置 301 重定向，上线后检查 404 |
| SEO 保护 | 标题、描述、内链、结构化数据在改版中丢失会导致排名下滑 | 迁移前保存元数据基线，上线后对照检查，提交新 sitemap，监测搜索表现 |
| 数据迁移 | 表单记录、预约数据、评论、商品等可能丢失或格式不兼容 | 迁移前备份，分类核对，上线前预演迁移 |
| 功能与集成 | 预约、支付、邮件等第三方系统需要重新对接 | 上线前逐项测试，保留回滚方案 |
| 域名与 DNS 切换 | 切换时可能出现短时中断或邮件问题 | 选低流量时段，预先降低 TTL，切换后验证 |
| 短期排名波动 | 改版后搜索排名可能出现短期波动，不能保证具体结果 | 沟通预期，不承诺具体排名或流量数字 |
